# Isolated load test — 2026-08-01

Commit under test: `78499c2`.

The test ran on the production VPS, but against a disposable PostgreSQL
database, a dedicated Redis instance and a dedicated API container. SMTP,
Matrix and S3 were disabled for the test environment. No production account or
production table was used. Media upload was intentionally out of scope.

## Functional workload

The HTTP workload covered health checks, registration, email verification,
profile lookup, current-user reads, a friend request, the incoming request list
and the matching notification.

| Scenario | Result |
| --- | ---: |
| Health requests | 200 / 200 |
| Registrations | 100 / 100 |
| Email confirmations | 100 / 100 |
| Current-user reads | 100 / 100 |
| Nickname lookups | 100 / 100 |
| Friend request and notification synchronization | passed |

## Realtime workload

SSE connections were ramped instead of opened in a single instantaneous burst.
The 500- and 1,000-connection stages ran from a separate load-generator
container on the private Docker network, avoiding the roughly 379-channel
limit observed in a single SSH port-forward.

| Connections | Connected | Failed | Average connect | p95 connect | Maximum connect |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 100 | 0 | 1,357.9 ms | 2,015.9 ms | 2,105.3 ms |
| 250 | 250 | 0 | 175.9 ms | 226.6 ms | 298.2 ms |
| 500 | 500 | 0 | 2,133.5 ms | 5,439.9 ms | 8,433.2 ms |
| 1,000 | 1,000 | 0 | 447.8 ms | 1,822.9 ms | 2,597.3 ms |

At the sampled peak of the 1,000-connection stage, the test API used about
285 MiB RAM and 39% CPU, PostgreSQL used about 105 MiB RAM and 13% CPU, and the
two API workers held roughly 532 and 535 file descriptors. Their `nofile` limit
was 65,535.

## Defect found and fixed

Before `78499c2`, every streaming response retained FastAPI's generator-backed
database dependency for the lifetime of the connection. The SQLAlchemy pool was
therefore exhausted after about 40 subscribers and later streams returned HTTP
500. SSE authentication now copies only the session and user identifiers in a
short-lived database session before returning the stream. Reconciliation also
buffers event payloads and closes its database session before yielding to a
potentially slow client.

The full backend suite passed after the fix: 151 tests.

## Interpretation

This proves that two API workers on the current host can establish and retain
1,000 mostly idle SSE subscriptions without media traffic. It does **not** prove
that the same VPS can serve 1,000 users simultaneously registering, loading
groups, posting chat messages or uploading files. Those mixed workloads need a
separate test profile, preferably from another machine, and external object
storage before media testing.

All disposable containers, test tokens and the test database were removed
after the run. Production API, web, Matrix and APK endpoints passed smoke tests
after deployment.
